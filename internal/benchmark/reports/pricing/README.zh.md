# 价格 Benchmark 报告

[English](README.md) · [运行指南](../../guides/pricing.zh.md) · [全部 Benchmark](../../README.zh.md)

## 最终结论

> **100 万、1000 万事件：迁移与历史重算均通过。**
> 在每秒 **50 条**持续输入下，消息全部落盘，**丢弃 0、写入错误 0**；原请求与 Token 核验一致，没有未回填费用。

**1000 万规模：首次价格迁移约 60 分钟，250 万条历史费用重算约 22 分钟。** 这是指定环境下的合成数据结果，不代表最大接收能力。

## 核心结果

| 指标 | 100 万事件 | 1000 万事件 |
| --- | ---: | ---: |
| **迁移／重算结果** | **通过／通过** | **通过／通过** |
| **首次价格迁移** | **6.68 分钟** | **59.55 分钟** |
| 最近 30 天重算量 | 25 万条 | 250 万条 |
| **历史重算耗时** | **2.49 分钟** | **21.68 分钟** |
| 期间接收且核验的消息 | 27,522 条 | 243,703 条 |
| 丢弃／写入错误 | **0／0** | **0／0** |
| 恢复后处理积压 | 4.07 秒 | 35.43 秒 |
| 整场 cgroup 内存峰值 | 2.79 GiB | **6.85 GiB** |
| 主库＋WAL/SHM＋备份峰值 | 1.71 GiB | **12.93 GiB** |

**计时口径：**迁移包含备份、事件费用回填、汇总费用和数据校验，不含生成测试数据及完整服务启动。重算量是最近 30 天的事件数，不是全库数量。内存峰值包含数据准备及文件缓存；磁盘为采样峰值。

## 查询表现

百万数据集上，同一 119 天范围，真实 HTTP 接口各预热一次、采样五次：

| 接口 | 重构前中位数 | 重构后中位数 | 本轮观察 |
| --- | ---: | ---: | --- |
| **总览** | 1,301.07 ms | **71.02 ms** | **中位耗时约为原来的 1/18.3** |
| 分析 | 1,706.19 ms | 1,757.33 ms | 中位耗时增加约 3%，样本不足以判断稳定差异 |

两版均返回 991,361 次请求、2,672,835,362 Token。此项不是千万数据或并发查询测试；模拟 CPA 返回 404，查询排除测试期间注入消息的日期。

## 较早版本数据库升级

独立的 **100 万条旧结构数据**测试最终通过：升级 **12.88 分钟**，333,333 条费用重算 **3.14 分钟**；48,064 条新消息全部落盘并核验，丢弃和写入错误均为 **0**。

**接收仍有等待：最长 26.00 秒。** 该场景包含旧结构升级，与上表只需价格迁移的数据库不同，耗时不能直接横比。

## 测试方法

1. 生成 120 天历史数据：90 天热表、30 天归档；500 个身份、50 个 Key、50 个模型、50 条价格规则，失败请求占 1%。
2. 执行首次价格迁移，持续以每秒 50 条向真实 SQLite inbox 写入；测试缓冲容量为 4,096。
3. 重算最近 30 天费用，随后恢复普通处理；核对事件、Token、汇总、接收消息数量和哈希。

较早版本升级场使用独立的 90 天全热表数据。资源每 50ms 采样，可能漏掉短峰值。固定输入速率不是最大容量测试，inbox 写入延迟不是 CPA 网络端到端延迟。
